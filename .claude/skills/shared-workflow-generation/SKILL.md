# Shared Workflow Generation

This skill orchestrates the parallel generation of workflow documentation for all agents in a Ralph Orchestra project.

## When to Use

Invoke this skill during Phase 11 of the PRD Starter wizard, after all agents, skills, and other files have been generated.

## Parallel Execution Strategy

Each workflow document is generated by a separate sub-agent working on its own file. This eliminates write conflicts and allows maximum parallelism:

## Your Process

### 1. Detect Enabled Agents

Read `prd.json.agents` to determine which agents are enabled:

```json
{
  "agents": {
    "pm": { "enabled": true },
    "developer": { "enabled": true },
    "techartist": { "enabled": true },
    "qa": { "enabled": true },
    "gamedesigner": { "enabled": true }
  }
}
```

### 2. Create Output Directory

Ensure the workflows directory exists:

```bash
mkdir -p docs/workflows
```

### 3. Launch Parallel Sub-Agents

Launch ALL workflow generation sub-agents in a single message using the Task tool:

```javascript
// Launch all enabled agent workflow generators in parallel
Task("workflow-generator", {
  agent_name: "pm",
  output_file: "pm-coordinator.md",
  source_file: "agents/pm/AGENT.md"
})

Task("workflow-generator", {
  agent_name: "developer",
  output_file: "developer.md",
  source_file: "agents/developer/AGENT.md"
})

Task("workflow-generator", {
  agent_name: "techartist",
  output_file: "techartist.md",
  source_file: "agents/techartist/AGENT.md"
})

Task("workflow-generator", {
  agent_name: "qa",
  output_file: "qa.md",
  source_file: "agents/qa/AGENT.md"
})

Task("workflow-generator", {
  agent_name: "gamedesigner",
  output_file: "gamedesigner.md",
  source_file: "agents/gamedesigner/AGENT.md"
})

// Always launch the development cycle generator
Task("devcycle-generator", {
  output_file: "development-cycle.md"
})
```

**Important:** Send all Task invocations in a SINGLE message. The Task tool will handle parallel execution automatically.

### 4. Wait for Completion

Wait for all sub-agents to complete. Each will confirm with:
```
Generated workflow documentation: {filename}
```

### 5. Verify Outputs

Check that all expected files were created:

```bash
ls -la docs/workflows/
```

Expected files:
- `pm-coordinator.md`
- `developer.md`
- `techartist.md`
- `qa.md`
- `gamedesigner.md`
- `development-cycle.md`

### 6. Generate Index

Create or update `docs/workflows/index.md` with links to all generated workflows:

```markdown
# Agent Workflows Index

Generated workflows for this project:

- **[Development Cycle](./development-cycle.md)** - Complete task lifecycle
- **[PM Coordinator](./pm-coordinator.md)** - Task assignment and coordination
- **[Developer](./developer.md)** - Feature implementation workflow
- **[Tech Artist](./techartist.md)** - Visual asset creation workflow
- **[QA Validator](./qa.md)** - Testing and validation workflow
- **[Game Designer](./gamedesigner.md)** - Design documentation workflow

## Quick Reference

See [README.md](./README.md) for workflow template standards.

---

*Generated by Ralph Orchestra PRD Starter*
```

## Agent Mapping

| Agent Name | Agent Type | Output File | Source File |
|------------|------------|-------------|-------------|
| PM | coordinator | `pm-coordinator.md` | `agents/pm/AGENT.md` |
| Developer | worker | `developer.md` | `agents/developer/AGENT.md` |
| Tech Artist | worker | `techartist.md` | `agents/techartist/AGENT.md` |
| QA | worker | `qa.md` | `agents/qa/AGENT.md` |
| Game Designer | worker | `gamedesigner.md` | `agents/gamedesigner/AGENT.md` |
| - | orchestration | `development-cycle.md` | (generated from orchestration docs) |

## Error Handling

If a sub-agent fails:

1. **Note the error** with which agent/file failed
2. **Continue with other agents** - don't stop the entire process
3. **Report summary** showing which workflows succeeded/failed
4. **Offer retry** for failed workflows

Common failure modes:
- Source `AGENT.md` not found → Skip this agent, log warning
- Output directory doesn't exist → Create it automatically
- Template not found → Use embedded template structure

## Success Criteria

- All enabled agent workflow files created
- `development-cycle.md` created
- All files follow the template structure
- YAML frontmatter present and valid in all files
- ASCII diagrams render correctly
- Index file created/updated with links

## Integration Points

This skill is invoked during:

- After all agent generation is complete
- Before displaying final summary to user
